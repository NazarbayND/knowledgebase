remains the long-term readiness benchmark.

## Checkpoint criteria

Mark a unit complete only when its specific acceptance criteria are met and you
can supply evidence. Review these general criteria alongside the unit's requirements:

- [ ] Explain the concept and its main constraints in your own words.
- [ ] Complete the required exercises and check their expected behavior.
- [ ] Record the written/design evidence; keep deferred practical work pending.
- [ ] Exercise a failure or edge case and explain the result.
- [ ] Record tradeoffs, remaining questions, and a link to the work.

These checkboxes describe a review checklist, not completed course milestones.
Copy the relevant criteria into a log entry when reviewing a specific unit.

## Evidence log

Use one entry per reviewed unit with the following fields:

| Field | Record |
| --- | --- |
| Unit | Chapter, exercise, or project name and relative documentation link |
| Date | Review date in `YYYY-MM-DD` format |
| Status | Not started, in progress, needs review, or complete |
| Evidence | Example path, command and result, commit, or test report |
| Reflection | What you learned, tradeoffs, and remaining questions |
| Next action | A concrete follow-up or the next learning unit |
