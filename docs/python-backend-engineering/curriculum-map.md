# Curriculum map

The original [16-week plan](course-plan.md) is now represented by ten phases and
twenty modules. All modules have lessons, written practice, interview prompts and
an assessment. Existing Phase 1–2 examples remain runnable. Practical projects
for Phases 3–10 are intentional placeholders.

## Depth and evidence

The [study and assessment guide](assessment-guide.md) defines scoring anchors and
written/practical evidence. Every module practice page has an answer-backed
self-check. Use the [glossary](glossary.md) for terminology and the
[SQL workbook](phase-5/module-9/query-workbook.md) for complete relational examples.

- **P0:** independently explain and implement; written study prepares the skill
  but does not substitute for implementation evidence.
- **P1:** apply mechanisms and justify tradeoffs under realistic constraints.
- **P2:** understand purpose, assumptions and failure modes before specialization.

The [eight design studies](phase-9/module-18/design-studies.md) supply all planned
design prompts, including the optional RAG specialization as a written scenario.
The [final competency review](phase-10/competency-review.md) preserves all eighteen
readiness items. Learner progress starts pending and changes only with evidence.

New service/project code, dependencies, cloud resources and deployment artifacts
are deferred. Excerpts in later lessons illustrate mechanisms and contracts;
syntax checks are not claims of runtime integration or production readiness.
